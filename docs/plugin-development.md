# Plugin Development

arxgen 2.0 exposes a stable plugin SDK for local files and installed npm packages.

Load plugins with `--plugin`:

```bash
arxgen list plugins --plugin ./examples/arxgen-plugin.mjs
arxgen --plugin ./examples/arxgen-plugin.mjs create \
  --name example-api \
  --language example \
  --framework api \
  --entity student \
  --field name:string \
  --out ./generated
```

Multiple plugins can be loaded by repeating `--plugin`, passing a comma-separated list to `--plugins`, or setting `ARXGEN_PLUGINS`.

## Contract

Plugins export a default object, named `plugin`, named `arxgenPlugin`, named `plugins`, or a factory function. A factory receives `{ apiVersion }`.

```js
export default ({ apiVersion }) => ({
  metadata: {
    name: "example-stack",
    version: "1.0.0",
    apiVersion,
    language: "example",
    framework: "api"
  },
  capabilities: {
    entities: true,
    crud: true,
    validation: ["zod"],
    orm: ["prisma"]
  },
  supports(config) {
    return config.language === "example" && config.framework === "api";
  },
  generateProject({ config, root, plugin }) {
    return [{ path: `${root}/README.md`, content: `# ${config.projectName}\nGenerated by ${plugin.name}.\n` }];
  },
  generateEntity({ root, entity }) {
    return [{ path: `${root}/entities/${entity.name}.txt`, content: `${entity.name}\n` }];
  }
});
```

`metadata.name`, `metadata.version`, and `metadata.apiVersion` are required. arxgen 2.x accepts plugin API major version `2`.

If `supports(config)` is omitted, `metadata.language` and `metadata.framework` are used for matching.

TypeScript plugin packages can import SDK types from the published package build:

```ts
import type { ArxgenPlugin } from "arxgen/dist/src/core/domain/pluginSdk.js";
```

## Lifecycle

arxgen calls hooks in this order:

1. `generateProject({ config, root, plugin })`
2. `generateEntity({ config, root, plugin, entity })` for each entity
3. `generateCrud({ config, root, plugin, entity })` for each entity
4. `generateAuth({ config, root, plugin, auth })` when `--auth` is set
5. `generateOrm({ config, root, plugin, orm })` when `--orm` is set

Every hook returns an array of generated files:

```js
{ path: "project-root/path/to/file", content: "file contents" }
```

`root` is the normalized project folder, derived from `--name`.

## Template Variables

Plugin authors receive the same project config used by built-in generators:

- `config.projectName`, `language`, `framework`, and `architecture`
- `config.entities[].name`
- `config.entities[].fields[].name`, `type`, `required`, `unique`, `indexed`, `defaultValue`, `length`, `precision`, and `scale`
- `config.database`, `orm`, `auth`, `authMode`, `validation`, `relations`, `docker`, `nginx`, and `redis`
- `config.languageVersion`, `frameworkVersion`, and `packageVersions`

## Capability Matrix

Use capability metadata so users can inspect plugin support with `arxgen list plugins`.

| Capability | Type | Meaning |
| --- | --- | --- |
| `entities` | boolean | Generates entity/domain files |
| `crud` | boolean | Generates CRUD workflow files |
| `dto` | boolean | Generates DTO/request/response files |
| `validation` | boolean or string[] | Supports validation generation |
| `pagination` | boolean | Supports list pagination |
| `auth` | string[] | Supported auth modes |
| `orm` | string[] | Supported ORM/database generators |
| `relations` | boolean | Supports relation metadata |
| `extendExistingProject` | boolean | Supports add/merge workflows |
| `schemaUpgrade` | boolean or `"partial"` | Supports schema upgrade |
| `productionReady` | boolean | Intended for production-oriented output |

## Testing Requirements

External plugins should include:

- Contract tests that validate metadata and hook return types.
- Fixture tests that run `arxgen --plugin <plugin> create ...`.
- Snapshot tests for representative generated files.
- Compatibility tests for unsupported API versions and unsupported project configs.

The arxgen repo includes these checks in `tests/plugin-sdk.test.mjs`.
